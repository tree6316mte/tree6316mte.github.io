      어제 필요해 보이는 것들을 북마크해서 바로 들어갈 수 있게 정리를 잘했다

      오늘 8시 58분쯤 되자 북마크 순서대로 QR 출석체크 한다음 잽에 들어가고 온보딩 트래커 키고 체크하면서 코드카타로 하루를 시작했다

      이후 코드타카를 끝내고 Spring 입문 강의를 듣는데 웹CS와 Java입문 강의와는 다르게 정리가 필요해 보여서 밑에 정리를 했다



      Spring 입문 강의

      먼저 프로젝트를 만들 때

      세팅

      1. 먼저 프로젝트 생성할 때 반드시 Spring Boot를 클릭해준다

      1. 생성 시 세팅은 Spring Web과 Lombok을 추가해준다

      1. 이후 설정을 열어서 자동 가져오기를 켜준다

      1. 우측 메뉴에 gradle 버튼 눌러서 gradle설정창을 킬 수 있음

      1. gradle설정은 Grovy나 Kotlin 언어로 작성 가능(강의에선 Grovy언어로 작성)

      1. 필요한 라이브러리가 있다면 gradle설정의 dependencies에 입력 후 아이콘 버튼 누르면 이렇게 외부 라이브러리에 다운


      HTTP란

      Request시에 Response 하는 것

      Method: 요청 방식 GET POST DELETE PUT PATCH
      Header: 요청이나 응답에 대한 Meta데이터 (부가 설명 데이터)
      Payload: 서버와 주고받는 핵심 데이터 (POST, PUT, PATCH에서 사용 가능)

      테스트용 API

      API 여기에 파일을 만든 뒤 아래와 같은 코드를 작성


      @RestController
public class HelloController {
    @GetMapping("/api/hello")
    public String hello(){
        return "Hello World!";
    }
}

      이렇게 코드를 작성 후 Get방식으로 호출 시 Response에서 Hello World!가 반환된다



      테스트 코드

      Junit을 이용하여 테스트 해볼 수 있다


      테스트를 할 클래스 위에서 우클릭할 시 테스트 만들 수 있다


      이곳에 테스트 코드가 만들어지고 단독 실행 가능함(Junit)


      해당위치에서 실행하려면 왼촉 초록색 실행 버튼을 클릭해서 실행된다


      밑에 창이 뜨고 실행이 다 됬을 때, 테스트 통과 체크하면 결과만 볼 수도 있다



      Lombok

      java프로젝트 진행 시 필요한 메서드나 생성자 등을 자동으로 생성해주는 좋은 친구이다

      일단 설정에서 어노테이션 처리 활성화를 킨다


      만약 처음 Spring 세팅할 때 설치를 안했다면 plugin에서 다시 설치하는게 가능하다


      Lombok 어노테이션 사용 방법은 위와 같이 사용된다


      @Getter : get 함수 자동생성
      @Setter : set 함수 자동생성
      @AllArgsConstructor : 멤버변수 모두 받는 생성자 자동생성
      @NoArgsConstructor : 멤버변수를 받지 않는 생성자 자동생성
      @RequiredArgsConstructor : final이 붙은 멤버변수를 받는 생성자 자동생성


      Spring 설정

      Spring Boot에서 자동으로 설정하고 있는 값을 수동으로 수정할 때 사용

      대략적인 위치 src > main > resources > application.properties

      application.yml라는 형식으로도 이 파일을 관리 할 수 있으나 그건 Spring에서 기본적으로 설정하는게 아니라 추가적인 작업이 필요해서 해당 강의에서는 다루지 않음



      Spring MVC란?

      수동으로 Servlet설정 하던 걸 이젠 Spring MVC 개념을 도입하여 자동으로 해준다

      도입 전

      도입 이전에 클라이언트 요청이 들어왔을때 서버의 Servlet이 어떻게 동작하는지 보여주는 사진
      Request(클라이언트 요청) -> Servlet(각종 로직 처리) -> Response(서버 응답)

      Spring MVC를 쓰지 않았을 때는 이렇게 요청을 처리 했고, 기능이 100개라면 100개의 서블릿 클래스를 직접 만들고 일일이 설정 파일에 등록 해야 하는 노가다가 있었음

      Servlet : Java를 사용하여 웹페이지를 동적으로 생성하는 서버측 프로그램 (Tomcat 안에서 동작함)

      @WebServlet(urlPatterns = "/user/login")
public class UserLoginServlet extends HttpServlet {
	@Override
  protected void doGet(HttpServletRequest request, HttpServletResponse response) {
		// ... 
	}
}

      예전에 직접 Servlet설정하려면 위와 같이 코드를 짜야 했다

      도입 후

      핵심 패턴인 Front Controller가 도입된 Spring MVC모습
      Request(클라이언트 요청) -> DispatcherServlet(자동으로 요청 분석 및 길 안내) -> Controller(로직 처리) -> View -> Response(서버 응답)

      예전에는 수동으로 Servlet을 하나하나 만들어 줘야 했다면, 지금의 스프링에서는 이렇게 요청 맨 앞에 DispatcherServlet을 두는 Front Controller패턴과 MVC패턴을 적용해 효율적으로 HTTP요청을 자동으로 처리하는 경지에 이른다

      이제는 개발자가 모든 요청마다 Servlet을 직접 작성하는 대신 DispatcherServlet이 맨 앞에서 모든 요청을 받아 알맞은 Controller에게 전달한다

      DispatcherServlet : 맨 앞단에서 Servlet 역할을 수행, Front Controller 패턴의 문지기

      그렇게 어노테이션(@Controller, @GetMapping)만 선언 해두면 Servlet을 수동으로 만들 지 않아도 맨 앞단 DispatcherServlet에 의해 자동으로 처리된다

      단, Controller단에서 계층 분리가 일어 날 수도 있음

      @Controller
@RequestMapping("/api")
public class HelloController {
    @GetMapping("/get")
    @ResponseBody
    public String get(){
        return "GET Method 요청!";
    }

    @PostMapping("/post")
    @ResponseBody
    public String post(){
        return "POST Method 요청!";
    }
}

      요즘 직접적인 Servlet설정 없이 위와 같이 코드를 짠다



      Controller란?

      Controller는 위에서 설명한 Spring MVC의 연장선이다

      도입 후 그림에 보이는 Controller의 역할이 해당 @Controller라는 어노테이션을 선언해서 사용하는 것이다.

      @RestController : @Controller 대신 쓰면 모든 메서드에 @ResponseBody 적용됨 @Controller : 해당 클래스가 클라이언트의 웹 요청을 받아 처리하는 담당자임을 알림
      @RequestMapping : 해당 클래스 내의 메서드들의 공통적인 최상위 경로를 묶음
      @ResponseBody : 반환값을 화면 HTTP 응답 본문에 데이터(문자열, JSON 등) 직접 반환 (미사용 시, “GET Method 요청!.html” 라는 웹페이지 파일 찾으려 시도함)
      @GetMapping : HTTP GET 방식의 클라이언트 요청
      @PostMapping : HTTP POST 방식의 클라이언트 요청
