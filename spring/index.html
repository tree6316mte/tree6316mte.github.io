        라이브러리(종속성) 세팅

        프로젝트 초기 세팅 시, build.gradle 또는 pom.xml에 추가하는 핵심 라이브러리들

        Spring Boot 생성할 때 아래 종속성은 기본으로 세팅해주면 편리하다

        1. Spring Web: 내장 Tomcat을 포함하며, REST API 및 웹 MVC 개발에 필수

        2. Thymeleaf: HTML 태그에 속성을 추가해 데이터를 동적으로 렌더링하는 서버 사이드 뷰 템플릿 엔진

        3. Lombok: @Getter, @Setter, @NoArgsConstructor 등 어노테이션 하나로 반복되는 코드를 줄여주는 꿀 라이브러리

        4. Spring Data JPA: 인터페이스만 작성해도 DB의 CRUD 처리가 가능하게 해주는, JPA를 한 단계 더 쉽게 쓰기 위한 모듈

        5. MySQL Driver: 애플리케이션과 MySQL DB가 통신할 수 있게 해주는 연결 드라이버

        폴더 만들기 (3Layer)

        "client -> controller -> service -> repository -> db" 이렇게 순서를 기억하면 된다

        1. controller: 함수들을 URL로 매핑(ex. @PostMapping)하여 service로 보냄
        2. service: 함수들을 @Transactional로 관리하며 서버의 실질적인 메인 함수 역할
        3. repository: 인터페이스를 JpaRepository<T>로 상속받아 자동으로 DB와 상호작용
        4. dto: 클라이언트에게 데이터를 주고받기 위해 만든 전용 객체
        5. entity: 데이터베이스의 테이블과 1:1로 매핑되게 만든 전용 객체

        폴더 예시

        "src\main\java\com\프로젝트명\" 폴더안에 "프로젝트명Application" 파일 옆에 서브 파일을 만든다

        초기 세팅 시, 3Layer 기준으로 폴더를 이렇게 미리 만들어 두는 것이 편하다

        예외처리

        기본 예외처리 throw(주로 service에서 일어남) 

        throw new ResponseStatusException(HttpStatus.CONFLICT);
throw new MyException(0); // 직접 만든 예외처리 클래스

        함수 내에서 return 대신 throw를 쓰면 된다

        개별 예외 클래스 만들기

        oooException.java
        public class MyException extends RuntimeException {
    public MyException(Long id) {
        super("오류발생 삐리릭. id=" + id);
    }
}

        만들어 놓고 전역 예외처리 핸들러에 추가해놓지 않으면 사용 불가하다

        개별 예외 클래스 전역 처리

        GlobalExceptionHandler.java
        @RestControllerAdvice
public class GlobalExceptionHandler {

    // 직접 만든 것도 여기 추가해줘야 사용 가능, Error 409 핸들러를 추가
    @ExceptionHandler(MyException.class)
    public ResponseEntity<ErrorResponse> handleFinished(
            MyException e, HttpServletRequest request) {
        return respond(HttpStatus.CONFLICT, e.getMessage(), request);
    }

    // DTO의 제약 조건(@NotBlank, @Min 등)을 어긴 데이터가 들어왔을 때 자동으로 발생하는 400 에러를 
    // 사용자가 읽기 편한 에러 메시지("어떤 필드 값이 올바르지 않습니다")로 가공해주기 위해 만듦
    @ExceptionHandler(MethodArgumentNotValidException.class)
    public ResponseEntity<ErrorResponse> handleBodyValidation(
            MethodArgumentNotValidException e, HttpServletRequest request) {
        FieldError fieldError = e.getBindingResult().getFieldError();
        String message = fieldError == null
            ? "요청 값이 올바르지 않습니다."
            : fieldError.getField() + " 값이 올바르지 않습니다: " + fieldError.getDefaultMessage();
        return respond(HttpStatus.BAD_REQUEST, message, request);
    }

    // URL 경로 파라미터나 쿼리 파라미터(@PathVariable 등)에 설정된 제약 조건을 어겼을 때 발생하는 400 에러를 처리하기 위해 만듦
    @ExceptionHandler(ConstraintViolationException.class)
    public ResponseEntity<ErrorResponse> handleParameterValidation(
            ConstraintViolationException e, HttpServletRequest request) {
        String message = e.getConstraintViolations().stream()
            .findFirst()
            .map(ConstraintViolation::getMessage)
            .orElse("요청 값이 올바르지 않습니다.");
        return respond(HttpStatus.BAD_REQUEST, message, request);
    }

    // 사용자가 보낸 JSON 데이터 형식이 완전히 깨졌거나, 숫자(Long)가 들어가야 할 파라미터에 문자열(String)이 들어오는 등 
    // 데이터 타입 변환 자체가 불가능할 때 발생하는 400 에러를 처리하기 위해 만듦
    @ExceptionHandler({HttpMessageNotReadableException.class, MethodArgumentTypeMismatchException.class})
    public ResponseEntity<ErrorResponse> handleUnreadable(Exception e, HttpServletRequest request) {
        return respond(HttpStatus.BAD_REQUEST, "요청 본문이나 파라미터 형식이 올바르지 않습니다.", request);
    }

    // 예외처리 return을 하기 쉽게 만듬
    private ResponseEntity<ErrorResponse> respond(HttpStatus status, String message, HttpServletRequest request) {
        return ResponseEntity.status(status).body(new ErrorResponse(status, message, request.getRequestURI()));
    }
}

        지금은 기본적인 것들 밖에 없지만 예외처리시 로그남기거나 해서 커스텀 해줄 수 있다

        @EntityListeners(AuditingEntityListener.class)

        oooEntity.java
        @Getter
@MappedSuperclass
@EntityListeners(AuditingEntityListener.class)
public abstract class BaseEntity { // 이건 extends 용

    @CreatedDate
    @Column(updatable = false)
    @Temporal(TemporalType.TIMESTAMP)
    private LocalDateTime createdAt;

    @LastModifiedDate
    @Temporal(TemporalType.TIMESTAMP)
    private LocalDateTime modifiedAt;
}

        아무데서나 가져다 쓸 수 있게 BaseEntity를 만든 뒤 @EntityListeners(AuditingEntityListener.class)를 추가해준다

        LocalDateTime을 멤버변수의 타입으로 지정하고 @CreatedDate과 @LastModifiedDate를 만들어 준다

        이후, BaseEntity에서 만든 시간을 싶은 Entity에 extends BaseEntity를 붙혀주면 된다



        RestClient

        RestClient는 외부 데이터를 가져올 때 사용한다

        oooClient.java
        @Component
public class MyRestClient {
    // json을 가져올 url 주소
    private static final String SOURCE_URL = "https://url";

    private final RestClient restClient = RestClient.create();

    public MyRestSource fetch() {
        return restClient.get()
                .uri(SOURCE_URL)
                .retrieve()
                .body(MyRestSource.class);
    }
}
        oooService.java
        @Service
@RequiredArgsConstructor
public class MyRestService {
    private final MyRestClient myRestClient;

    @Transactional
    public MyRestResponse Function(){
        MyRestSource source = myRestClient.fetch();
        return new MyRestResponse(
            source.getMeta().getSeason().getId()
        );
    }
}
        oooSource.java || dto
        @Getter
public class MyRestSource {
    private Meta meta;

    @Getter
    public static class Meta {
        private Season season;
        private LocalDateTime generatedAt;
        private int schemaVersion;
        private long totalRecords;

        @Getter

        그리고 Source class는 static을 이용해서 정적 중첩 클래스로 JSON의 계층 구조를 객체로 매핑할 때 알맞게 만들 수 있다
